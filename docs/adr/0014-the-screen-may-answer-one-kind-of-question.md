# จอตอบคำถามได้หนึ่งชนิด และตอบด้วยการแตะเท่านั้น

ADR-0007 ปิดเรื่อง tap ไว้ด้วยเหตุผลที่ยังจริงอยู่ทุกข้อ: จอนี้เป็น resistive จุดเดียว อ่านค่าเป็น ADC
ดิบและมี noise · การบังคับให้ต้อง "ลากเกินระยะ" ทนต่อการเผลอโดนได้ ซึ่งสำคัญกับของที่วางบนโต๊ะ
ให้มือปัดผ่านทั้งวัน · และ tap แลกมาด้วยความสามารถที่ page rotation ทำแทนได้อยู่แล้ว

**ข้อสุดท้ายคือข้อที่เปลี่ยน** — คำขออนุญาตของ Claude Code เป็นสิ่งที่ page rotation ทำแทนไม่ได้
มันไม่ใช่การเลือกดูหน้าไหน แต่เป็นการตอบคำถามที่มีคำตอบสองทาง และอีกฝั่งค้างรออยู่จริงๆ

## ทำไมไม่ใช้ทิศของการลาก

ทางที่ไม่ต้องแตะเลยมีอยู่ และเกือบได้ทำ: ปัดขวา = อนุญาต ปัดซ้าย = ปฏิเสธ ใช้กลไกเดิมทั้งหมด
ไม่ต้องแตะ ADR-0007 เลยสักตัวอักษร

ที่ไม่เอาเพราะ **ทิศไม่ใช่ภาษาที่พูดเรื่องนี้ได้อย่างปลอดภัย** สามข้อ

หนึ่ง — การปัดคือท่าที่มืออยู่ในโหมด "เปลี่ยนหน้า" อยู่แล้วตลอดทั้งวัน วันที่คำขอโผล่ขึ้นมาพอดี
ตอนนิ้วกำลังจะปัด การปัดครั้งนั้นจะกลายเป็นคำตอบโดยที่ไม่มีใครตั้งใจตอบ · การแตะไม่มีปัญหานี้
เพราะมันไม่ใช่ท่าที่จอนี้เคยใช้ทำอะไรเลย

สอง — ทิศไม่มีความหมายในตัวมันเอง ต้องจำเอาว่าขวาคืออะไร และมันจำผิดได้ทุกครั้งที่ไม่ได้ใช้
มาสองสัปดาห์ · ปุ่มที่เขียนว่า Deny กับ Allow ไม่ต้องจำ

สาม — และข้อนี้ตัดสิน: **การปัดผิดทางไม่มีทางกู้คืน** เพราะมันไม่มีระยะกลาง ปัดไปทางไหนก็เป็น
คำตอบเสมอ ส่วนการแตะมีพื้นที่ว่างระหว่างปุ่มให้ตกได้ — และการตกลงในพื้นที่ว่างแปลว่าไม่มีอะไร
เกิดขึ้น ซึ่งเป็นผลลัพธ์ที่ถูกต้องของการเล็งไม่แม่น

## ราคาที่จ่าย: พิกัดที่หยาบ

`docs/hardware.md` เขียนไว้ตรงๆ ว่าเลขสี่มุมยัง "ไม่ใช่ค่า calibrate ที่แม่นพอจะแปลงเป็นพิกเซล"
เพราะทั้งสี่มุมวัดที่ระยะ 20px จากขอบ ขอบจริงจึงเป็นการลากเส้นออกไปนอกช่วงที่วัด

ADR นี้ไม่ได้แก้ข้อนั้น มัน **ยอมรับมันแล้วออกแบบให้ทน** — `h_origin`/`v_origin` ใน
`layout.toml` คือการลากเส้นย้อนอีก 20px จากจุดที่วัดจริง ความคลาดที่ขอบไกลราว 4-5px

ตัวเลขนั้นใช้ไม่ได้กับปุ่มขนาดปกติ แต่ใช้ได้สบายกับปุ่มครึ่งจอที่มีช่องว่างคั่นกลาง ซึ่งเป็น
รูปเดียวที่การ์ดนี้จะมี · **ข้อจำกัดกำหนดรูปของ UI ไม่ใช่ UI กำหนดว่าต้องไป calibrate ใหม่**

## ผลที่ตามมา

`ct_touch_poll` เดิมยังอยู่และยังคืนแค่ทิศการปัด — ผู้เรียกที่ไม่สนใจการแตะไม่ต้องรู้ว่ามีอะไร
เปลี่ยน · ตัวใหม่ `ct_touch_poll_event` คืนทั้งสองอย่าง และเรียกซ้อนกันไม่ได้เพราะทั้งคู่อ่าน
ชิปตัวเดียวกัน

การแตะรายงาน **จุดที่นิ้วลง ไม่ใช่จุดที่ยก** — จุดลงคือจุดที่คนเล็ง ส่วนจุดยกคือจุดที่นิ้วไหลไปถึง
ตอนถอนออก

จอที่ไม่มีชิปสัมผัสบัดกรีมา (ADR-0007 เขียนไว้ว่ามีจริง) ยังใช้งานได้เต็มรูปแบบเหมือนเดิม —
คำขออนุญาตบนบอร์ดแบบนั้นจะไม่มีใครตอบ แล้วมันหมดเวลากลับไปถามที่ terminal ตามปกติ
ซึ่งคือพฤติกรรมก่อนมีฟีเจอร์นี้ทั้งหมด

**กติกาว่าอะไรอนุญาตได้ไม่ได้อยู่ที่นี่** — Mac เป็นคนตัดสิน (`Risk`) และตัดสินอีกครั้งตอนรับ
คำตอบกลับ · เฟิร์มแวร์ที่ถูกแก้ให้ส่ง allow กับทุกใบจึงเปลี่ยนอะไรไม่ได้ ADR-0001 ยังจริง
คำต่อคำ: บอร์ดไม่ได้ตัดสินใจ มันแค่รับนิ้ว
